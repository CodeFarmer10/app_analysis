## 1. 项目概述

### 1.1 项目背景

随着移动互联网的快速发展，诈骗类APP日益猖獗，已成为危害社会安全的重要威胁。此类恶意应用往往伪装成正常软件，通过诱骗用户安装并实施欺诈行为，给用户带来巨大的财产损失与隐私泄露风险。

为有效打击电信网络诈骗，保障公民合法权益，亟需建立一套科学、高效的诈骗APP分析系统，以支持公安、网络安全及相关机构对可疑应用程序进行快速检测、分析与溯源。

### 1.2 项目目标

- 提供自动化的APK样本静态分析能力，快速提取文件结构、权限、证书等关键信息
- 提供动态沙箱溯源能力，捕获APP运行时的真实行为（网络请求、界面截图、操作日志等）
- 以可视化看板形式直观呈现任务统计与设备运行状态
- 输出规范化PDF分析报告，供办案人员归档留存
- 支持多设备并行分析，提升分析效率

### 1.3 适用范围

本文档适用于以下场景：

- 公安机关对涉案诈骗APP进行技术取证分析
- 网络安全机构对可疑应用实施预防性检测
- 企业安全部门对员工使用的APP进行风险排查

## 2. 系统总体架构

### 2.1 系统架构概述

诈骗APP分析系统采用前后端分离架构，核心由 Web 管理平台、分析引擎、分析设备池三大模块组成。用户通过浏览器访问 Web 管理平台，提交分析任务；后端分析引擎负责协调静态分析与动态溯源任务的调度执行；分析设备池由若干 Android 真机或模拟器组成，负责动态运行待检测 APK 并回传分析数据。

### 2.2 主要模块

| 模块名称 | 核心功能 | 说明 |
|---|---|---|
| 用户认证模块 | 登录鉴权、会话管理、用户管理 | 支持用户名/密码方式登录；管理员可新增/删除用户；普通用户可修改密码 |
| 任务管理模块 | 任务提交、状态跟踪、搜索过滤 | 支持APK文件上传和URL链接两种提交方式 |
| 静态分析引擎 | APK解包、文件特征提取 | 提取MD5、证书、权限、组件、SO文件等静态特征 |
| 动态溯源引擎 | 沙箱运行、行为采集、流量抓取 | 实时记录运行截图、操作日志和网络流量 |
| 报告生成模块 | PDF报告输出 | 自动整合静动态分析结果，生成规范化报告 |
| 看板统计模块 | 任务统计展示 | 实时显示总任务量、今日任务及关键指标 |
| 设备监控模块 | 设备状态管理 | 支持设备列表查看、添加、删除及状态监控 |

## 3. 功能需求详细说明

### 3.1 用户认证与账户管理

#### 3.1.1 功能描述

系统提供基于用户名和密码的登录认证机制，并支持管理员进行用户账户管理，确保仅授权用户可访问系统且账户生命周期可控。

#### 3.1.2 功能需求

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
|---|---|---|---|
| F-01-01 | 用户名密码登录 | 用户通过输入用户名和密码完成身份认证，验证通过后进入系统主界面 | 高 |
| F-01-02 | 登录失败提示 | 用户名或密码错误时，系统给出明确的错误提示，不泄露具体错误原因 | 高 |
| F-01-03 | 会话管理 | 登录成功后生成有效会话Token，超时或手动退出后自动失效 | 高 |
| F-01-04 | HTTPS传输 | 登录请求必须通过HTTPS加密传输，防止密码明文泄露 | 高 |
| F-01-05 | 管理员新增用户 | 系统管理员可新增普通用户或管理员用户，密码仅以哈希形式存储 | 高 |
| F-01-06 | 管理员删除用户 | 系统管理员可删除指定用户；禁止删除当前登录管理员，且至少保留一个管理员账户 | 高 |
| F-01-07 | 普通用户修改密码 | 登录用户可通过“旧密码 + 新密码”方式修改自身密码；新旧密码不得相同 | 高 |

#### 3.1.3 界面要求

- 登录页面包含用户名输入框、密码输入框（密码字符隐藏）、登录按钮
- 支持键盘回车键触发登录操作
- 登录成功后跳转至系统看板主页

### 3.2 任务上传

#### 3.2.1 功能描述

用户可通过两种方式向系统提交待分析的APP样本：直接上传APK安装包文件，或提供APP的下载链接URL。两种方式均支持批量提交。URL方式采用异步下载机制，系统在后台自动下载，不阻塞用户操作。

#### 3.2.2 功能需求

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
|---|---|---|---|
| F-02-01 | APK文件批量上传 | 支持一次性选择并上传多个.apk文件，每个文件独立创建分析任务，单文件大小建议限制在500MB以内 | 高 |
| F-02-02 | URL批量提交 | 支持一次性输入多条HTTP/HTTPS下载链接（每行一条），系统为每条链接独立创建任务 | 高 |
| F-02-03 | 异步下载机制 | URL任务提交后立即返回任务ID，系统在后台异步执行下载，任务状态显示"下载中"，下载完成后自动流转至静态分析阶段 | 高 |
| F-02-04 | 文件格式校验 | 上传前对文件格式进行校验，非APK文件拒绝上传并提示用户；URL提交时系统在下载完成后校验文件格式 | 高 |
| F-02-05 | 重复检测 | 根据文件MD5进行重复性检测，若已存在相同样本则提示用户并给出已有任务链接 | 中 |
| F-02-06 | 上传进度显示 | 批量上传时展示整体进度及各文件独立进度，提交完成后自动跳转至任务列表 | 中 |
| F-02-07 | 备注信息 | 支持在提交时填写任务描述/备注，便于后期检索与管理 | 低 |

### 3.3 任务列表

#### 3.3.1 功能描述

系统以列表形式展示所有已提交的分析任务，并实时显示每个任务的当前处理状态，便于用户了解分析进度。

#### 3.3.2 任务状态流转

任务按以下阶段依次流转：

| 状态 | 状态标识 | 描述 | 预计耗时 |
|---|---|---|---|
| 下载中 | `downloading` | 系统正在从URL下载APK文件（URL提交方式，异步执行） | 根据网速而定 |
| 下载失败 | `download_failed` | URL不可达、非APK格式、下载超时等原因导致失败，记录具体失败原因 | 终态 |
| 静态分析中 | `static_analyzing` | 正在对APK文件进行解包与静态特征提取 | 1~5分钟 |
| 静态分析失败 | `static_failed` | APK解包异常、文件损坏或分析工具报错导致失败，记录具体失败原因 | 终态 |
| 等待设备 | `waiting_device` | 静态分析完成，等待设备池中有可用设备 | 视设备负载而定 |
| 动态溯源中 | `dynamic_tracing` | 已分配设备，正在真机/模拟器上运行APK，采集行为数据 | 5~30分钟 |
| 动态溯源失败 | `dynamic_failed` | 设备连接中断、APP崩溃或溯源超时导致失败，已采集的部分数据仍可查看，记录具体失败原因 | 终态 |
| 已完成 | `completed` | 静态分析与动态溯源均已完成，可查看结果并下载报告、APK、流量包 | 终态 |

#### 3.3.3 列表字段说明

| 字段名称 | 说明 | 备注 |
|---|---|---|
| 任务ID | 系统自动生成的唯一标识符 | |
| 文件名/下载链接 | APK文件上传时显示原始文件名；URL方式提交时显示原始下载链接 | 两种上传方式分别显示对应来源信息 |
| 图标 | 从APK中提取的应用启动图标缩略图 | 分析完成前显示占位图 |
| APP名称 | APK包内提取的应用名称 | 分析完成前显示"分析中" |
| 包名 | Android应用包名（packageName） | 分析完成前显示"—" |
| 文件MD5 | APK文件的MD5哈希值 | 用于去重与检索 |
| 提交时间 | 任务创建的时间戳 | 格式：YYYY-MM-DD HH:mm:ss |
| 当前状态 | 任务当前所处阶段 | 参见状态流转说明 |
| 分配设备 | 执行动态溯源的设备名称/ID | 未分配时显示空（"—"） |
| 操作 | 查看结果、下载APP、下载报告、下载流量包等操作入口 | 根据状态动态展示可用操作 |

#### 3.3.4 其他功能需求

- 列表支持分页显示，每页默认显示20条记录，支持自定义每页显示数量
- 支持按提交时间倒序/正序排列
- 状态列使用不同颜色标签区分（进行中：蓝色，已完成：绿色，失败：红色）
- 列表支持实时刷新（建议自动刷新间隔30秒）或手动刷新

### 3.5 任务结果查看

#### 3.5.1 功能描述

任务完成后，用户可进入详情页查看完整的静态分析和动态溯源结果。结果页面分为两大标签页呈现，信息内容丰富、层次清晰。

#### 3.5.2 静态分析结果

静态分析无需运行APK，通过解包分析其内部结构与资源，提取以下信息：

| 信息类别 | 字段名称 | 说明 |
|---|---|---|
| 基础信息 | 文件MD5 | APK文件的MD5哈希值，用于唯一标识文件 |
| 基础信息 | 文件大小 | APK文件的字节大小，展示为可读格式（如 12.5 MB） |
| 基础信息 | APP名称 | 应用的中文/英文显示名称 |
| 基础信息 | 应用图标 | 提取APK内的启动器图标，原图展示 |
| 基础信息 | 版本信息 | versionName（显示版本）和versionCode（内部版本号） |
| 证书信息 | 证书MD5 | 签名证书的MD5摘要 |
| 证书信息 | 证书SHA1 | 签名证书的SHA1摘要 |
| 证书信息 | 证书SHA256 | 签名证书的SHA256摘要 |
| 权限信息 | 声明权限列表 | AndroidManifest.xml中声明的所有权限，标注危险权限 |
| 组件信息 | Activity列表 | 应用内所有Activity组件，标注入口Activity |
| 组件信息 | Provider列表 | 应用声明的ContentProvider组件及其权限属性 |
| 组件信息 | Service列表 | 应用注册的Service组件及其属性 |
| 本地库 | SO文件列表 | APK中包含的Native动态链接库文件（.so）清单 |

#### 3.5.3 动态溯源结果

动态溯源通过在真实设备或受控沙箱环境中运行APP，采集其实际运行行为。后台自动从设备池中分配可用设备执行分析；若当前无可用设备，任务进入等待队列，待设备空闲后自动调度。结果以列表形式呈现，每条记录包含以下信息：

| 字段名称 | 说明 | 示例/格式 |
|---|---|---|
| 操作 | 系统执行的测试动作描述 | 点击登录按钮、输入手机号、滑动屏幕等 |
| 操作结果 | 操作执行后的系统反馈或APP响应 | 成功/失败/超时，或具体响应内容摘要 |
| 运行截图 | 操作前后的APP界面截图 | 图片缩略图展示，支持点击放大查看 |
| 流量日志 | 操作触发的网络请求/响应记录，包含以下字段：源IP、目的IP、源端口、目的端口、协议类型、域名、URL、解析IP | 列表展示，支持展开查看完整请求/响应体 |

#### 3.5.4 流量日志字段说明

| 字段名称 | 说明 | 备注 |
|---|---|---|
| 源IP | 发起网络请求的设备IP地址 | 即分析设备的内网/出口IP |
| 目的IP | 请求目标服务器的IP地址 | |
| 源端口 | 客户端使用的本地端口号 | |
| 目的端口 | 目标服务器监听的端口号 | 如80、443、8080等 |
| 协议类型 | 网络层/应用层协议 | 如TCP、UDP、HTTP、HTTPS、DNS等 |
| 域名 | 请求目标的域名（如有） | DNS查询或HTTP Host字段提取 |
| URL | 完整请求URL（HTTP/HTTPS请求） | 包含路径与查询参数 |
| 解析IP | 域名经DNS解析后对应的IP地址 | 便于追踪C2服务器真实地址 |

#### 3.5.5 设备自动分配机制

- 动态溯源任务提交后，系统后台自动从设备池中选取状态为"空闲"的设备进行分配
- 若当前设备池中无可用设备，任务进入等待队列，状态显示为"等待设备"
- 设备空闲后按队列顺序自动调度，无需人工干预
- 任务列表中显示当前分配的设备名称/ID；未分配时显示"—"（等待中）
- 分配成功后任务状态自动流转为"动态溯源中"

#### 3.5.6 界面交互要求

- 静态分析与动态溯源结果分Tab页呈现，默认显示静态分析Tab
- 权限列表中，危险权限（Dangerous Permission）应用红色标注
- 动态溯源截图支持点击放大查看，支持左右切换
- 流量日志支持展开/折叠查看详情，长内容支持滚动
- 页面加载过程中显示Loading状态，大数据量分页加载

### 3.6 文件下载功能

#### 3.6.1 功能描述

#### 3.6.2 功能需求

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
|---|---|---|---|
| F-06-01 | 下载APP（APK） | 支持从任务列表或详情页下载原始APK安装包文件，便于人工复核与留存 | 高 |
| F-06-02 | PDF报告生成与下载 | 系统在任务完成后自动生成PDF分析报告；用户可在任务列表或详情页一键下载 | 高 |
| F-06-03 | 静态分析报告内容 | 报告包含文件基础信息（含文件大小）、证书信息、权限清单、组件信息、SO库列表 | 高 |
| F-06-04 | 动态溯源报告内容 | 报告包含操作步骤、操作结果、运行截图（嵌入）、关键流量日志（含8项流量字段） | 高 |
| F-06-05 | 流量包下载 | 支持下载动态溯源过程中采集的完整原始流量数据（PCAP格式），供专业人员深入分析 | 高 |
| F-06-06 | 报告封面信息 | 报告封面包含任务ID、样本MD5、分析时间、系统名称等基础信息 | 中 |
| F-06-07 | 文件命名规范 | APK：`{APP名称}_{MD5前8位}.apk`；报告：`{APP名称}_{MD5前8位}_{分析日期}.pdf`；流量包：`{APP名称}_{MD5前8位}_{分析日期}.pcap` | 低 |

### 3.7 看板（数据统计面板）

#### 3.7.1 功能描述

系统首页以看板形式展示关键统计数据，为管理员和分析员提供平台整体运行状态的直观概览。

#### 3.7.2 看板指标说明

| 指标名称 | 说明 | 数据来源 |
|---|---|---|
| 总任务数 | 系统中所有历史任务的总数量 | 任务数据库统计 |
| 今日提交任务数 | 当日（0:00~24:00）新增提交的任务数量 | 按日期过滤统计 |
| 今日完成任务数 | 当日完成分析的任务数量 | 按日期和状态过滤统计 |
| 分析中任务数 | 当前正处于分析流程中的任务数量 | 实时查询进行中状态 |
| 在线设备数 | 当前在线且可用的分析设备数量 | 设备监控模块实时数据 |
| 任务成功率 | 已完成任务数 / 总任务数 × 100% | 计算指标 |

#### 3.7.3 其他需求

- 看板数据每30秒自动刷新一次，也可手动触发刷新
- 可视化图表展示近7天/30天任务趋势（折线图或柱状图）
- 关键数字指标以大字体突出显示，便于快速阅读

### 3.8 设备监控

#### 3.8.1 功能描述

设备监控模块负责对用于动态溯源分析的Android设备（真机或模拟器）进行统一管理，支持查看设备状态、添加新设备及移除设备。

#### 3.8.2 功能需求

## 4. 非功能性需求

### 4.1 性能需求

| 性能指标 | 需求描述 | 目标值 |
|---|---|---|
| 静态分析耗时 | 单个APK完成完整静态分析所需时间 | ≤ 5分钟 |
| 动态溯源耗时 | 单个APK完成动态溯源分析所需时间 | ≤ 30分钟 |
| 并发任务数 | 系统支持同时进行分析的任务数量 | ≥ 设备数量 |
| 页面响应时间 | Web页面加载与操作响应时间 | ≤ 3秒 |
| PDF报告生成时间 | 任务完成后报告生成完毕的时间 | ≤ 2分钟 |
| 系统可用性 | 系统年度可用率（SLA） | ≥ 99% |

### 4.2 安全需求

- 所有数据传输必须使用HTTPS/TLS 1.2+加密
- 用户密码在数据库中存储时必须使用强哈希算法（如bcrypt）加密存储，不得明文保存
- 系统应具备完整的操作审计日志，记录关键操作（登录、任务提交、报告下载等）
- API接口实施Token鉴权机制，防止未授权访问
- APK样本文件在沙箱环境中运行，与宿主系统严格隔离，防止恶意代码逃逸
- 支持基于角色的访问控制（RBAC），不同用户角色具有不同功能权限

### 4.3 可用性与界面需求

- 系统采用响应式设计，支持主流浏览器（Chrome、Firefox、Edge）访问
- 界面语言支持中文，错误提示信息应明确、友好
- 关键操作（删除设备、重置任务等）需二次确认，防止误操作
- 系统应提供操作帮助文档或工具提示（Tooltip）

### 4.4 可扩展性需求

- 系统架构支持横向扩展，可通过增加分析设备数量提升整体吞吐量
- 分析引擎支持插件化扩展，后期可集成更多检测规则和威胁情报源
- API接口符合RESTful规范，便于与第三方系统（如SIEM、案件管理系统）集成

## 5. 数据存储与管理需求

### 5.1 数据存储需求

- **APK样本文件**：支持大文件存储，建议采用对象存储（如MinIO/S3）管理样本文件
- **分析结果数据**：存储于关系型数据库（如MySQL/PostgreSQL），支持高效查询
- **运行截图文件**：以图片格式存储，建议统一管理于对象存储
- **流量日志数据**：采用结构化格式存储，支持全文检索
- **PDF报告文件**：生成后存储于文件服务，提供持久下载链接

### 5.2 数据保留策略

- **APK样本文件**：永久保留（作为电子证据）
- **分析结果数据**：永久保留
- **运行截图和流量日志**：保留不少于180天
- **系统操作审计日志**：保留不少于365天

## 6. 接口与集成需求

### 6.1 内部接口总览

系统前后端通过RESTful API通信，所有接口均需携带 `Authorization: Bearer {token}` 请求头（登录接口除外）。接口按功能模块分组说明如下。

#### 6.1.1 认证模块

| 接口名称 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 用户登录 | POST | `/api/auth/login` | 提交用户名+密码，验证成功返回Token及用户信息；失败返回错误提示 |
| 修改密码 | POST | `/api/auth/change-password` | 登录用户使用旧密码校验后修改自身密码 |
| 退出登录 | POST | `/api/auth/logout` | 无状态退出，服务端校验Token后返回成功，客户端清理本地会话 |
| 用户列表（管理员） | GET | `/api/users` | 管理员获取用户列表（用户名、角色、创建时间） |
| 新增用户（管理员） | POST | `/api/users` | 管理员新增用户，可指定角色（`admin`/`user`） |
| 删除用户（管理员） | DELETE | `/api/users/{id}` | 管理员删除用户，遵循“不可删自己、至少保留一个管理员”约束 |

#### 6.1.2 任务管理模块

| 接口名称 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 批量上传APK | POST | `/api/tasks/upload` | multipart/form-data，支持同时上传多个APK文件，每个文件独立创建任务，返回任务ID列表 |
| 批量提交URL | POST | `/api/tasks/url` | 请求体传入URL数组，系统异步下载每条链接对应的APK，立即返回任务ID列表 |
| 获取任务列表 | GET | `/api/tasks` | 分页查询，支持page/size参数；同时作为过滤入口（详见搜索接口） |
| 搜索/过滤任务 | GET | `/api/tasks?md5=&name=&package=&status=&start=&end=&page=&size=` | 附加查询参数实现多维度搜索：`md5`（文件哈希）、`name`（APP名称模糊）、`package`（包名前缀/精确）、`status`（`downloading` / `download_failed` / `static_analyzing` / `static_failed` / `waiting_device` / `dynamic_tracing` / `dynamic_failed` / `completed`）、`start`/`end`（提交时间范围，ISO 8601格式），支持多参数AND组合 |
| 获取任务详情 | GET | `/api/tasks/{id}` | 返回指定任务的基础信息、当前状态、分配设备、静态分析结果及动态溯源结果 |
| 获取任务状态 | GET | `/api/tasks/{id}/status` | 轻量接口，仅返回当前状态字段及分配设备信息，供前端轮询任务进度使用 |

#### 6.1.3 分析结果模块

| 接口名称 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 获取静态分析结果 | GET | `/api/tasks/{id}/static` | 返回文件大小、MD5、APP名称、图标URL、版本、证书（MD5/SHA1/SHA256）、权限列表、Activity/Provider/Service列表、SO文件列表 |
| 获取动态溯源结果 | GET | `/api/tasks/{id}/dynamic` | 返回溯源操作记录列表（操作、操作结果、截图URL）及流量日志列表（源IP、目的IP、源端口、目的端口、协议类型、域名、URL、解析IP），支持分页 |

#### 6.1.4 文件下载模块

| 接口名称 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 下载APK文件 | GET | `/api/tasks/{id}/apk` | 返回原始APK安装包，文件名格式：`{APP名称}_{MD5前8位}.apk` |
| 下载PDF报告 | GET | `/api/tasks/{id}/report` | 返回静动态分析PDF报告，文件名格式：`{APP名称}_{MD5前8位}_{分析日期}.pdf` |
| 下载流量包 | GET | `/api/tasks/{id}/pcap` | 返回动态溯源采集的原始PCAP流量包，文件名格式：`{APP名称}_{MD5前8位}_{分析日期}.pcap` |
| 获取运行截图 | GET | `/api/tasks/{id}/screenshots/{seq}` | 返回指定序号的运行截图（PNG），供详情页点击放大查看使用 |

#### 6.1.5 设备管理模块

| 接口名称 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 获取设备列表 | GET | `/api/devices` | 返回所有注册设备的基础信息、实时状态（在线/离线/分析中）及当前任务ID |
| 获取设备详情 | GET | `/api/devices/{id}` | 返回设备品牌型号、系统版本、分辨率、可用存储、最后心跳时间等详细信息 |
| 添加设备 | POST | `/api/devices` | 注册新设备至设备池，请求体含连接地址（IP:Port 或序列号）及自定义名称 |
| 修改设备信息 | PUT | `/api/devices/{id}` | 更新设备自定义名称等可编辑字段 |
| 删除设备 | DELETE | `/api/devices/{id}` | 从设备池中移除指定设备；若设备有进行中任务则拒绝删除并返回提示 |

#### 6.1.6 看板统计模块

| 接口名称 | 方法 | 路径 | 说明 |
|---|---|---|---|

## 7. 约束条件与假设

### 7.1 技术约束

- 动态溯源需要物理Android设备或Android模拟器支持，系统需要ADB网络访问权限
- 静态分析依赖Apktool、dex2jar等开源工具的稳定运行
- PDF报告生成需要服务端具备相应的渲染库支持（如WeasyPrint、wkhtmltopdf）

### 7.2 假设条件

- 分析设备（Android手机/模拟器）已预先完成系统配置，包括root权限、ADB调试开启等
- 网络环境允许分析设备访问外部网络，以便捕获APP的真实网络行为
- 系统运行环境具备足够的存储空间用于样本文件和分析数据的持久化
- 运营方已获得相关法律授权，分析对象均为依法取证的涉案样本
